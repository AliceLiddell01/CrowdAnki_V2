# CrowdAnki V2

**CrowdAnki V2** — современный аддон для Anki, предназначенный для совместной работы с колодами, карточками и медиафайлами через системы контроля версий.

Проект разрабатывается с чистого листа под актуальные версии Anki и не является форком или доработкой устаревшей кодовой базы оригинального CrowdAnki.

---

## Архитектура проекта

Проект разделен на три уровня ответственности:

1. **Go-ядро (`core/`)** — основной язык проекта. Нативное ядро отвечает за ключевые вычислительные задачи, форматы данных и бизнес-логику. Компилируется без внешних зависимостей и без CGO.
2. **Python-адаптер (`addon/`)** — минимальный интеграционный слой для Anki. Отвечает исключительно за регистрацию аддона в среде Anki/Qt и передачу управления Go-ядру. Не содержит независимой бизнес-логики и не выполняет прямых записей в базу SQLite Anki.
3. **PowerShell-инструментарий (`build/`)** — служебные сценарии автоматизации на PowerShell 7 (`pwsh`) для кроссплатформенной сборки `.ankiaddon`, запуска линтеров, статических анализаторов и очистки артефактов.

## Целевое окружение

- **Целевая версия Anki**: `26.09.2` (Python 3.13)
- **Компилятор Go**: `1.26+` (зафиксирован в `core/go.mod`)
- **Интерпретатор Python**: `3.13` (зафиксирован в `.python-version`)
- **Оболочка сценариев**: PowerShell 7+ (`pwsh`)

## Требования для локальной разработки

Для работы с проектом на рабочей машине необходимы:

1. **Go** (версия 1.26 или новее).
2. **Python** (версия 3.13) с установленным линтером Ruff:
   ```bash
   pip install ruff
   ```
3. **PowerShell 7** (`pwsh`).
4. Модуль **PSScriptAnalyzer** для PowerShell:
   ```powershell
   Install-Module -Name PSScriptAnalyzer -Scope CurrentUser
   ```

## Локальные проверки качества

Перед отправкой изменений запустите единый локальный сценарий проверок:

```powershell
pwsh -File build/check.ps1
```

Сценарий последовательно выполняет:
- Проверку форматирования Go (`gofmt`), анализ (`go vet`), тесты (`go test`) и сборку ядра.
- Проверку Python-кода линтером Ruff (`ruff check`), проверку форматирования (`ruff format --check`) и компиляцию синтаксиса (`py_compile`).
- Анализ сценариев PowerShell с помощью PSScriptAnalyzer.
- Проверочную сборку пакета `.ankiaddon` с верификацией его структуры.

---

## Сборка пакета аддона (.ankiaddon)

Для сборки устанавливаемого пакета выполните:

```powershell
pwsh -File build/build.ps1
```

Сценарий автоматически:
1. Компилирует Go-ядро под целевую платформу (по умолчанию под текущую ОС разработчика).
2. Копирует файлы Python-адаптера в изолированный каталог сборки.
3. Генерирует `manifest.json` на основе параметров из `build/config.json`.
4. Формирует ZIP-архив с расширением `.ankiaddon` в каталоге `dist/`.
5. Проверяет корректность внутренней структуры архива:
   - `manifest.json` и `__init__.py` расположены непосредственно в корне архива;
   - отсутствуют файлы разработки, исходники Go, скрипты сборки и кэши (`__pycache__`, `*.pyc`).

### Дополнительные параметры сборки

Сценарий сборки поддерживает явное указание целевой ОС и архитектуры для кросс-компиляции:

```powershell
pwsh -File build/build.ps1 -TargetOS linux -TargetArch amd64
pwsh -File build/build.ps1 -TargetOS darwin -TargetArch arm64
```

> **Особенность целевых платформ Unix (Linux / macOS)**:  
> При распространении нативного исполняемого файла внутри ZIP-архива стандартный механизм распаковки аддонов Anki может не сохранять флаг исполняемости (`chmod +x`). В дальнейшем на стороне Python-адаптера будет предусмотрена автоматическая установка прав на запуск для извлеченного бинарника.

## Экспорт в формат CrowdAnki V2

Аддон интегрируется непосредственно в штатный диалог экспорта Anki:

1. Откройте в главном меню Anki пункт **Файл → Экспорт...** (или нажмите значок шестерёнки рядом с нужной колодой и выберите **Экспорт**).
2. В выпадающем списке **Формат экспорта** выберите **CrowdAnki V2 — каталог**.
3. Выберите экспортируемую колоду (будет экспортирована выбранная корневая колода вместе со всеми вложенными подколодами).
4. При необходимости включите опцию **Включить медиафайлы**.
5. Под параметрами экспорта автоматически отобразится блок **Будет экспортировано** с предварительной сводкой:
   - количество колод;
   - количество заметок;
   - количество карточек;
   - количество типов заметок;
   - количество и общий размер используемых медиафайлов.
6. Нажмите кнопку **Экспорт** и выберите целевой каталог на диске. Имя каталога не привязано к имени колоды и может быть любым.

### Структура каталога экспорта

Экспорт формирует изолированное детерминированное представление коллекции:

```text
<выбранный каталог>/
├── crowdanki.json       # Файл-маркер формата и версии схемы (schema_version: 1)
├── decks.json           # Плоский детерминированный список колод с parent_id
├── notes.jsonl          # Заметки (1 строка = 1 JSON-объект с именованными полями и тегами)
├── cards.jsonl          # Карточки и их структурная привязка к колодам
├── media.json           # Манифест медиафайлов с размерами и SHA-256
├── note_types/          # Спецификации используемых типов заметок
│   └── <id>.json        # Поля, шаблоны карточек и CSS конкретного типа
└── media/               # Копии используемых уникальных локальных медиафайлов
```

### Особенности формата и архитектуры экспорта

- **Межпроцессный транспорт**: Python-адаптер извлекает данные коллекции через официальный публичный API Anki и передает сформированный DTO скомпилированному бинарному Go-ядру через subprocess JSON transport (`stdin -> crowdanki-core export -> stdout`). Go-ядро выполняет валидацию, форматирование, хеширование медиа и запись на диск.
- **Staging и атомарность записи**: формирование файлов экспорта выполняется Go-ядром в изолированном временном каталоге (`os.MkdirTemp`). Перенос файлов в целевую директорию (`CommitStagedExport`) производится только после успешной генерации всех сущностей, с детерминированным удалением устаревших управляемых файлов (включая очистку `media/` при отключении медиа) и гарантированной защитой сторонних пользовательских файлов.
- **`notes.jsonl` самодостаточен**: поля заметок хранятся в виде словаря `"имя_поля": "значение"`, что позволяет читать и редактировать их человеку или ИИ без необходимости заглядывать в `note_types/`. Пользовательский HTML и Unicode сохраняются без искажений.
- **Детерминированность**: порядок записей и сериализация строго упорядочены (по GUID, именам, ID). Два последовательных экспорта неизменной колоды дают побайтно идентичные текстовые файлы. В формате отсутствуют локальные пути разработчика и случайные timestamps.
- **Безопасность путей и каталогов**: экспорт проверяет пути от path traversal и запрещает экспорт в системные профили Anki. Повторный экспорт разрешен только в пустой каталог либо в существующий проект CrowdAnki V2 (с валидным `crowdanki.json` поддерживаемой версии схемы). Посторонние непустые каталоги защищены от перезаписи.
- **Оптимизация медиа**: копируются исключительно реально задействованные локальные файлы (включая статические шрифты и изображения шаблонов). Потоковый расчет SHA-256 выполняется прямо во время копирования.
- **Поддержка скоупов экспорта**: поддерживается экспорт выбранной колоды со всеми подколодами или всей коллекции. Экспорт произвольной выборки заметок из браузера (`NoteIdsLimit`) в текущей версии не поддерживается: пользователю выводится явное предупреждение без выполнения некорректного экспорта. Настройки колод (`deck_options`), FSRS-параметры, история повторений и состояние планировщика (`scheduling`) намеренно не входят в базовый экспорт.

## Импорт из формата CrowdAnki V2

Импорт реализован как детерминированная синхронизация состояния выбранного CrowdAnki V2-проекта с целевой коллекцией Anki с отображением полного предварительного плана изменений (ImportPlan) в отдельном окне.

### Порядок работы

1. В главном меню Anki выберите пункт **Файл → CrowdAnki V2: Импортировать…**.
2. В открывшемся окне нажмите **Выбрать другую папку…** и укажите каталог с проектом CrowdAnki V2 (содержащий `crowdanki.json`).
3. Аддон автоматически запустит фоновый анализ:
   - Go-ядро проверит валидность и целостность проекта;
   - Python-адаптер соберёт снимок текущего состояния целевой коллекции для импортируемого дерева колод;
   - Планировщик Go построит детерминированный `ImportPlan` и выявит возможные конфликты.
4. В окне отобразится:
   - **Сводка проекта**: количество колод, заметок, карточек, типов заметок и медиафайлов;
   - **Бейджи планируемых изменений**: количество добавляемых, обновляемых, перемещаемых, удаляемых объектов и конфликтов;
   - **Предупреждения о деструктивных операциях**: явное информирование, если планируется удаление заметок, карточек или дочерних колод;
   - **Интерактивное дерево деталей**: просмотр конкретных изменений с фильтрацией (`Все`, `Заметки`, `Карточки`, `Колоды`, `Типы заметок`, `Медиа`, `Конфликты`);
   - **Опция импорта медиа**: чекбокс `☑ Импортировать медиафайлы` (по умолчанию включён).
5. При отсутствии блокирующих конфликтов нажмите **Импортировать** для применения изменений.

### Ключевые семантические правила импорта

- **Источник истины внутри scope**: экспортируемое дерево корневых колод проекта (`root_decks`) определяет управляемый `import scope`. Любые колоды за пределами этого дерева считаются внешними и никогда не модифицируются и не удаляются.
- **Сохранение прогресса обучения карточек**: обновление существующих заметок (полей, тегов, стилей, шаблонов) и перемещение карточек между колодами выполняется через публичный API Anki без пересоздания объектов. Интервалы, due, ease, количество повторений и история FSRS строго сохраняются.
- **Защита карточек вне scope (Out-of-scope protection)**: если заметка удалена из импортируемого проекта, но имеет хотя бы одну карточку в колоде вне управляемого scope, сама заметка **не удаляется** и карточки вне scope сохраняются. Удаляются исключительно карточки этой заметки, находящиеся в управляемом scope.
- **Сопоставление сущностей**:
  - Колоды сопоставляются по относительному пути/структуре в дереве (`Name`), а не по локальным ID;
  - Заметки сопоставляются строго по переносимому `Note.guid`;
  - Карточки сопоставляются по логическому ключу `(note_guid, ord)`;
  - Типы заметок сопоставляются по имени и проверяемой структуре.
- **Обработка конфликтов типов заметок**: поддерживаются безопасные модификации (обновление CSS, шаблонов, добавление новых полей в конец). Неоднозначные изменения (удаление полей или переименования без маппинга) считаются конфликтом и блокируют импорт проекта.
- **Семантика медиафайлов**:
  - Отсутствующие файлы добавляются в `collection.media`;
  - Совпадающие по имени и хэшу SHA-256 пропускаются (no-op);
  - Файлы с одинаковым именем, но разным хэшем вызывают **конфликт медиа**, блокирующий импорт при включенной опции медиа;
  - Глобальное хранилище медиа Anki защищено: файлы из `collection.media` никогда не удаляются при импорте колоды.
- **Безопасность и бэкап**: перед выполнением любых деструктивных изменений аддон инициирует создание резервной копии через официальный механизм `col.create_backup(force=True)`.

## Регламент работы с Git

- Ветка `main` содержит исключительно стабильное состояние проекта. Прямые коммиты в `main` запрещены.
- Вся работа ведется в тематических ветках, названных на английском языке по смыслу решаемой задачи (например, `infrastructure/repo-setup`, `export/base-export`, `import/basic-import`), без привязки к порядковым этапам разработки.
- Изменения вливаются в `main` только через Pull Request после обязательного прохождения проверок в GitHub Actions CI.
